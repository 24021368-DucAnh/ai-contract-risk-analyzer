# Data quality CI — 21/11/2026

The Data repository now has a GitHub Actions workflow for pull requests to any branch (including the stacked PR #24 base), pushes to main, and manual dispatch after the workflow is available on the default branch.

Each PR checks its GitHub-generated merge result on Ubuntu and Windows with Python 3.10. It installs the pinned dependencies from requirements-ci.txt, checks whitespace against the event base, lints scripts/ and tests/ with the existing Ruff configuration, and runs the full public test suite. Checkout and setup-python are pinned to the official v6 commit SHAs verified on 21/11/2026. The workflow requests contents:read only, does not persist checkout credentials, and has no deployment, Gold-writing, source-intake or PR-approval step.

Tests use the files already eligible to be in the public checkout and synthetic fixtures. No restricted files, model key, legal-source PDF download or cloud inference is supplied to CI. The existing restricted-input skips remain explicit in pytest output: HDLD007 source-intake content is withheld pending redistribution permission, and two held-out equivalent-gate tests need absent restricted Gold. No new skip or continue-on-error was added to obtain a green result. These skips are not evidence of held-out or legal acceptance; review the reasons if the skip count changes.

Synthetic converter tests do not create actual D2 Gold or prove a human adjudication. CI success establishes the declared technical checks for the tested tree only; it does not approve legal text/effectivity, data rights, all 21 risk labels, M8 quality or a merge. Existing Owner decisions remain separate. The workflow does not alter the Pipeline Data pin or publish restricted data.

GitHub-hosted runners use their own ephemeral Python environment with the same major/minor and pinned tool versions. A green result is reported only after the actual remote jobs complete. Review/merge order remains #22 -> #23 -> #24; verify or retarget #24 after #23 merges, then rerun checks on its new base. No workflow step pushes or merges branches.
